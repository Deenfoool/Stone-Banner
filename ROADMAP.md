# Stone & Banner — Roadmap

> Total-conversion мод для Minecraft: мир, блоки, сущности и визуальный язык остаются узнаваемым Minecraft, но управление, камера, экономика, развитие поселений и стратегические системы полностью переосмысливаются.

## Основные принципы проекта

- **Minecraft должен визуально оставаться Minecraft.** Не превращаем его в отдельную voxel-игру: сохраняем блоки, биомы, рельеф, деревья, воду, деревни, мобов и пропорции Minecraft.
- **Камера и управление — не ванильные.** Основной режим — перспективная камера сверху/сзади в духе Baldur's Gate 3 с плавной сменой дистанции между персонажем, группой и поселением.
- **Бой идёт в реальном времени.** Без бросков кубиков и без пошаговой системы.
- **Игрок начинает как отдельный человек, а не готовый правитель.** Свой отряд, население и поселение нужно получить через игровой процесс.
- **Строительство остаётся физическим Minecraft-строительством.** Здания состоят из настоящих блоков и существуют в настоящем мире.
- **Мир имеет стратегическую ценность.** Каждый чанк получает собственный ресурсный профиль, поэтому выбор территории, разведка, торговля и расширение становятся важными решениями.
- **NPC — не просто ресурс Population +1.** У жителей есть дом, община, профессия, отношения, причины оставаться или переселяться.

# Phase 3 — Territory & Chunk Resource System

> Одна из центральных систем Stone & Banner. Каждый Minecraft-чанк `16×16` имеет собственный профиль территории и стратегическую ценность.

## 3.1 Профиль каждого чанка
- [ ] **Плодородие** — земледелие, пастбища и аграрные системы.
- [ ] **Лесные ресурсы** — доступность древесины и восстановление леса.
- [ ] **Каменные ресурсы** — камень, песок, глина и другие нерудные материалы.
- [ ] **Рудный потенциал** — железо, уголь, медь, золото и другие залежи.
- [ ] **Водные ресурсы** — вода, рыба, орошение, реки и озёра.
- [ ] **Пригодность территории** — строительство, проживание и инфраструктура.

## 3.2 Факторы расчёта
Характеристики чанка не являются случайным набором цифр и выводятся из Minecraft-мира.

### Биом
- [ ] Plains → высокий аграрный потенциал.
- [ ] Forest / Taiga → высокий лесной потенциал.
- [ ] Mountains / Stony биомы → камень и повышенный рудный потенциал.
- [ ] Desert → песок, слабое плодородие, дефицит воды.
- [ ] Swamp → вода, особые растения, сложность строительства.
- [ ] Остальные биомы получают собственные профили и модификаторы.

### Высота и рельеф
- [ ] Высота влияет на аграрный, каменный и рудный потенциал.
- [ ] Измерять перепад высот внутри чанка.
- [ ] Ровная земля повышает строительный потенциал.
- [ ] Сложный рельеф увеличивает стоимость/время строительства.
- [ ] Холмы и склоны могут давать оборонительные преимущества.

### Вода, климат и влажность
- [ ] Наличие реки/озера внутри чанка.
- [ ] Расстояние до постоянной воды.
- [ ] Температура, влажность и климатический профиль биома.
- [ ] Влияние на сельское хозяйство, лес, культуры и рыболовство.
- [ ] В будущем — речная логистика и торговля.

### Подземная геология
- [ ] Независимый детерминированный geological noise по seed мира.
- [ ] Геологические зоны переходят через границы чанков.
- [ ] Богатые месторождения образуют крупные пятна/жилы, а не раздаются равномерно каждому чанку.
- [ ] Совместимость с фактической Minecraft-генерацией руд либо корректное наложение на неё.

## 3.3 Особенности территории
Чанк может иметь одну или несколько редких особенностей:

- [ ] Плодородная / пойменная почва.
- [ ] Густой лес.
- [ ] Глинистые почвы.
- [ ] Каменный пласт.
- [ ] Богатые залежи железа / угольный пласт.
- [ ] Родник.
- [ ] Рыбные воды.
- [ ] Ягодники / лекарственные растения.
- [ ] Заброшенная шахта.
- [ ] Древние руины.
- [ ] Естественная гавань / удобная переправа.
- [ ] Другие world-feature traits.

Особенности дают реальные механические бонусы/штрафы.

## 3.4 Возобновляемые и ограниченные ресурсы

### Возобновляемые
- [ ] Древесина.
- [ ] Урожай / плодородие.
- [ ] Рыба.
- [ ] Дикие животные.
- [ ] Некоторые растения.

### Ограниченные
- [ ] Железо.
- [ ] Уголь.
- [ ] Медь.
- [ ] Золото.
- [ ] Другие руды.
- [ ] Отдельные каменные/глиняные месторождения, если это оправдано балансом.

## 3.5 Истощение и восстановление
- [ ] Вырубка снижает лесной потенциал; лес восстанавливается естественно или через посадку.
- [ ] Чрезмерное земледелие снижает плодородие.
- [ ] Севооборот/удобрение/отдых земли восстанавливают плодородие.
- [ ] Чрезмерный вылов снижает рыбный ресурс.
- [ ] Рудные месторождения не восстанавливаются.
- [ ] Мир сохраняет изменения профиля территории.

## 3.6 Разведка территории
Игрок не знает точные характеристики мира сразу.

- [ ] **Уровень 0 — неизвестно:** только визуально очевидная информация.
- [ ] **Уровень 1 — разведано:** биом, примерное плодородие, лес, вода.
- [ ] **Уровень 2 — изучено:** камень, поверхностные ресурсы, признаки руд, особенности.
- [ ] **Уровень 3 — геология:** тип, богатство и диапазон оценочного запаса месторождения.

Пример:

```text
Чанк [18, -7]
Биом: Равнина
Плодородие: Высокое
Лес: Низкий
Камень: Средний
Железо: Не исследовано
Вода: Высокая доступность
Пригодность: Высокая
Особенность: Пойменные почвы (+20% урожайности)
```

## 3.7 Territory Overlay UI
- [ ] Стратегический слой территории.
- [ ] Видимые границы чанков.
- [ ] Карточка чанка по наведению.
- [ ] Heatmap: плодородие, лес, камень, руды, вода, строительство, контроль.
- [ ] Цветовой слой не должен перекрывать Minecraft-мир.
- [ ] Неисследованные ресурсы остаются неизвестными.

## 3.8 Стратегическое значение
Игровой цикл территории:

**разведка → оценка → специализация → добыча → истощение → торговля / расширение → конфликт**

- [ ] Сельскохозяйственные районы ценны для еды.
- [ ] Леса — для древесины.
- [ ] Горы — для добычи.
- [ ] Реки и переправы — для инфраструктуры, торговли и обороны.
- [ ] Бедная ресурсами территория всё равно может быть стратегически важной.

# Phase 4 — Деревни, жители, репутация и миграция

> Первая социальная система игры. Игрок не получает население бесплатно: сначала он входит в существующий мир деревень и постепенно заслуживает право привлекать людей.

## 4.1 Старт новой игры
- [ ] Игрок спавнится **один**, сразу с новым BG3-подобным управлением.
- [ ] Нет готового отряда и собственного поселения.
- [ ] Первые минуты — получение ресурсов первой необходимости, еды и простейших инструментов.
- [ ] Следующая естественная цель — найти ближайшую Minecraft-деревню.
- [ ] Vanilla tutorial-loop «ударь дерево → верстак → шахта» не должен быть основным progression loop Stone & Banner.

Целевой ранний цикл:

**странник → первая деревня → помощь общине → доверие → помощники → лагерь → переселенцы → собственное поселение**

## 4.2 Деревня как община
Каждая деревня получает собственный постоянный объект `VillageCommunity`:

- [ ] Уникальная идентичность/название деревни.
- [ ] Центр общины.
- [ ] Население и профессии.
- [ ] Домашняя территория.
- [ ] Локальная репутация игрока.
- [ ] Староста.
- [ ] Доска объявлений.
- [ ] Список активных проблем/заданий.
- [ ] История важных событий: рейды, помощь игрока, потери, переселения.

## 4.3 Староста
- [ ] В каждой полноценной деревне **всегда есть староста**.
- [ ] Староста является представителем общины и главным источником информации о деревне.
- [ ] Через старосту доступны сведения о состоянии деревни, отношении к игроку и части возможностей переселения.
- [ ] Староста не обязан быть бессмертным: при смерти должен существовать механизм выбора/назначения нового старосты.
- [ ] Внешность старосты остаётся в Minecraft-стилистике, без превращения NPC в персонажей другой игры.

## 4.4 Доска объявлений и задания
- [ ] Возле центра деревни/колокола размещается **доска объявлений**.
- [ ] На доске публикуются задания от конкретных жителей и от самой общины.
- [ ] У каждого задания есть автор, причина и награда.
- [ ] Доска используется для поиска заданий, но **сдаётся задание лично тому NPC, который его разместил**.
- [ ] Если автор задания погиб/недоступен, предусмотреть логичную передачу задания старосте или родственнику/общине.
- [ ] Задания должны исходить из состояния мира, а не быть только случайными MMO-квестами.

Примеры:
- принести еду после плохого урожая;
- добыть инструменты или материалы;
- найти пропавшего жителя;
- уничтожить угрозу рядом с деревней;
- сопроводить торговца;
- помочь восстановить дом;
- разведать опасную территорию;
- отбить нападение.

## 4.5 Репутация деревни и известность
Не использовать один глобальный числовой «уровень героя» для всего мира.

### Локальная репутация
Каждая деревня отдельно помнит отношение к игроку.

- [ ] Выполнение задания повышает локальную репутацию.
- [ ] Размер изменения зависит от сложности и важности задания.
- [ ] Помощь без активного квеста также может менять репутацию.
- [ ] Торговля, подарки, защита жителей и другие действия могут давать небольшое изменение.
- [ ] Кражи, убийства, предательство, ущерб деревне и провал важных обязательств снижают репутацию.

Рабочие уровни репутации:

1. **Чужак** — минимальное доверие.
2. **Знакомый** — доступны простые поручения и торговля.
3. **Друг общины** — больше заданий и локальная помощь.
4. **Союзник** — разрешены серьёзные контракты и часть переселений.
5. **Защитник** — высокий уровень доверия после значимой помощи деревне.

Названия уровней можно позже скорректировать после UI-прототипа.

### Общая известность / слава
- [ ] Отдельный медленно растущий показатель, известный нескольким поселениям.
- [ ] Обычные мелкие квесты почти не влияют на него.
- [ ] Крупные события — спасение деревни от рейда, победа над серьёзной угрозой, известные достижения — увеличивают его заметнее.
- [ ] Известность облегчает первое знакомство с новыми деревнями, но **не заменяет локальную репутацию**.

## 4.6 Домашняя территория жителей
- [ ] У каждого обычного жителя есть `homeCommunity` и `homeTerritory`.
- [ ] Базовая домашняя зона деревни распространяется примерно до **2 чанков от её территории/центра**; точную формулу определить при прототипировании.
- [ ] Обычный житель не должен бесконечно следовать за игроком по миру только потому, что на него нажали Recruit.
- [ ] За пределами домашней зоны он отказывается от обычных рабочих/сопровождающих приказов и объясняет причину через UI/реплику.
- [ ] Это не невидимая физическая стена: ограничения объясняются его привязанностью к дому и общине.

## 4.7 Три уровня участия NPC

### Местный помощник
- [ ] Доступен относительно рано.
- [ ] Может работать, защищать деревню или недолго сопровождать игрока.
- [ ] Ограничен домашней территорией деревни.

### Спутник
- [ ] Требует большего доверия, причины и/или оплаты.
- [ ] Может путешествовать далеко вместе с игроком.
- [ ] Всё ещё считает исходную деревню своим домом.

### Переселенец
- [ ] Полностью переносит `homeCommunity` в поселение игрока.
- [ ] Требует подготовленного места назначения: жильё, продовольствие и базовую безопасность.
- [ ] После переселения его домашняя территория связана уже с поселением игрока.

## 4.8 Переселение безработных за изумруды
Идею «купить жителя» оформляем как **контракт / оплату переселения**, а не собственность над NPC.

- [ ] Безработных жителей привлечь проще, чем жителей с важной профессией, домом и семьёй.
- [ ] Изумруды могут использоваться как единовременная выплата/подъёмные при переселении.
- [ ] Требуется минимальный уровень репутации деревни; одной большой суммы недостаточно для абсолютно чужого игрока.
- [ ] У игрока должно существовать пригодное место назначения: жильё + запас еды.
- [ ] Цена зависит от профессии, навыков, благополучия исходной деревни и спроса на рабочую силу.
- [ ] Бедный/безработный житель без семьи может согласиться значительно легче.
- [ ] Кузнец, фермер или другой критически важный специалист может быть недоступен, пока деревня сама нуждается в нём.
- [ ] Деревня может временно блокировать переселение, если её население слишком мало.

## 4.9 Динамические события как альтернативный путь к доверию
Игрок не обязан гриндить доску объявлений.

Пример — нападение на деревню:

1. Игрок в mid-game исследует мир и находит новую деревню.
2. На неё начинается или уже идёт рейд.
3. Игрок вмешивается без заранее взятого задания.
4. Игра фиксирует вклад: уничтоженные нападающие, спасённые жители, защита ключевых объектов.
5. После успешной обороны деревня мгновенно выдаёт крупный прирост локальной репутации.
6. При достаточном вкладе игрок получает уровень доверия, позволяющий сразу обсуждать найм, спутников или переселение части жителей.
7. Крупное спасение также может дать немного общей известности.

- [ ] Репутация должна начисляться за **действия в мире**, а не только за квестовые флаги.
- [ ] Случайные события должны создавать альтернативные истории прохождения.
- [ ] Масштаб награды зависит от реального вклада игрока.
- [ ] Нельзя получить максимальное доверие, просто находясь рядом с рейдом.

## 4.10 Семьи, профессии и мотивация
- [ ] Профессия влияет на готовность уйти.

# Первый вертикальный срез

Минимальная версия, которая уже должна ощущаться как Stone & Banner:

1. Minecraft-мир визуально полностью сохранён.
2. Перспективная камера и управление персонажем сверху/сзади.
3. Игрок появляется один и находит существующую Minecraft-деревню.
4. В деревне всегда есть староста и доска объявлений.
5. Один NPC публикует задание, которое нужно сдать лично ему.
6. Выполнение задания повышает локальную репутацию деревни.
7. Один безработный житель может стать местным помощником в пределах домашней территории.
8. Домашняя территория ограничивает обычного жителя примерно радиусом до двух чанков без искусственной невидимой стены.
9. После достаточного доверия и подготовки жилья/еды житель может согласиться на переселение.
10. Изумруды используются как подъёмные/контракт на переселение, а не как покупка NPC.
11. HUD: население, продовольствие, казна, благополучие + отдельные материалы.
12. Профиль территории для каждого чанка и Territory Overlay.
13. Одна ферма, урожайность которой зависит от чанка.
14. Один лесорубный участок, который истощает лесной ресурс.
15. Одно железное месторождение, которое нужно обнаружить и разведать.
16. Blueprint постройки и рабочий, физически строящий её из Minecraft-блоков.
17. Базовый склад и суточное производство/потребление.
18. Одно динамическое нападение на деревню, где реальный вклад игрока заметно повышает репутацию без заранее взятого квеста.

После этого можно расширять систему в сторону семей, развитой миграции, армии, торговли, городов, фракций и политики.
