# QA — 09.10.2026: восстановление рабочих заданий (P5)

Продолжение незакрытой 1.12/P5, без расширения G7 и изменения игровой логики.

## Проверенные сценарии

- `CitizenQueueGameTests.reloadedWorkerReacquiresPublishedWorkExactlyOnce`: сохранение незавершённого рабочего состояния NPC проходит через сжатый NBT и загрузку. Опубликованное задание остаётся в Job Board, исполнительная аренда/маршрут сбрасываются, приоритет работы сохраняется. Обычные серверные тики заново выбирают работу, удаляют дерево и создают ровно один физический лог; через дополнительные 20 тиков нет повторного задания или дропа. Переноска в этой сцене отключена, чтобы изолировать физическую добычу.
- `CitizenQueueGameTests.compressedReloadClearsMixedAndMovementQueues`: смешанная очередь и очередь путевых точек очищаются после сжатого NBT round-trip. Наниматель сохраняется, NPC не воспроизводит старое движение на последующих тиках.
- `CitizenJobBoardTest.legacySaveWithoutNextIdDoesNotReuseExistingJobIdentity`: старый формат без `NextId` загружается через сжатый NBT; завершённая работа не появляется снова, существующее задание сохраняется, новые ID не пересекаются с ним.
- `CitizenJobBoardTest.reloadedReservationBelongsOnlyToNewClaimant`: загрузка сбрасывает старую аренду. Прежний исполнитель не может продлить, завершить или освободить работу, которую уже получил другой NPC.

## Прогоны

- Первый серверный прогон завершился одним отказом нового теста добычи: ожидался лог на земле, но включённая по умолчанию HAULING переносила его в инвентарь. Исправлена **подготовка теста**, не игровой код: отключена переноска перед сохранением. Не считать этот отказ найденным/исправленным багом мода.
- Повторный `--offline --no-daemon test build verifyGameTests` на Java 17: **389 JUnit**, 0 failures/errors/skipped; **все 142 обязательных GameTest** прошли в 01:08:44 (Москва), `BUILD SUCCESSFUL in 2m 14s`, код выхода 0. Новый `clean` не выполнялся; предыдущий чистый прогон 387/140 от 08.10 записан отдельно.
- Сборка `build/libs/stonebanner-0.1.0-alpha.49.jar` успешна. Добавлены только тесты и документация; игровое поведение этого JAR не менялось.

## Границы результата

NBT round-trip внутри GameTest не равен полноценному перезапуску dedicated-server с непустой очередью. Существующие работы должны сохраняться как мировые задания и заново приобретаться NPC; временные маршруты/боевые приказы намеренно не сериализуются. Выход игрока без выгрузки NPC и загрузка сущности — разные сценарии.

P5 остаётся открытой: ручные P0–P4, команды и права через настоящий клиент, перезапуск сервера с непустыми заданиями, миграция реально более старого пользовательского мира и нагрузочная приёмка. Прошлый dedicated smoke с копией текущего мира описан в [отчёте 08.10](QA_2026_10_08.md). Новый dedicated/client запуск в этом продолжении не выполнялся.

## P5 — срок резервирования работ после отката игрового времени (09.10.2026)

- В `CitizenJobBoard.reserve` и `availableJobs` используется единое правило истечения аренды: после 300 тиков без обновления **либо немедленно при `gameTime < reservedTick`**, что может случиться при восстановлении снимка мира.
- Старое резервирование из будущего таймлайна теперь не блокирует другого NPC бесконечно. Владельца каждой аренды по-прежнему проверяют `touch`, `release` и `complete`; новая работа не должна выполняться дважды.
- Добавлены 4 JUnit-сценария на прямое повторное назначение, выбор задач после отката, точную границу 300 тиков и добровольное обновление аренды исходным рабочим.
- **Статус:** исправление и регрессионные тесты добавлены в исходники. Результаты `test build verifyGameTests` для этого изменения ещё не подтверждены; ручная проверка dedicated server/старого мира также открыта. Ранее зафиксированные 389 JUnit + 142 GameTest относятся к предыдущему HEAD.

## P5 — устойчивость загрузки реестра заданий (09.10.2026)

- Устранено **тихое затирание разных задач с одинаковым сохранённым ID**: разные работы восстанавливаются с отдельными IDs, следующий ID не пересекается с исходными допустимыми записями.
- Повторный одинаковый `WorkType + BlockPos` больше не создаёт две работы после загрузки; отсутствующий `Target` не превращается в фантомный заказ на `(0,0,0)`.
- Неизвестное или неверно типизированное поле `RequiredSkill` **не даёт рабочему неограниченный доступ**: небезопасную запись пропускаем. При восстановлении исправлений SavedData помечается грязной для записи.
- Защита от переполнения счётчика ID запрещает публикацию с отрицательным ID после достижения `Long.MAX_VALUE`.
- Добавлены 4 JUnit-сценария (дублирующиеся ID, недопустимый skill, отсутствующая цель, дубль задачи). **Автоматические Gradle / Forge тесты на этом HEAD ещё не запускались.** P5 остаётся открытой.

## P5 — завершение задания только действующим исполнителем

- `CitizenJobBoard.complete` теперь удаляет задание **только** при совпадении ненулевого UUID заявителя с текущей арендой. Отмена/принудительное удаление по-прежнему выполняется через явные `remove` / `removeAt`.
- Это закрывает класс ошибок: после перезагрузки или освобождения аренды прежний NPC не должен удалять опубликованную работу, которую никто пока заново не взял.
- Добавлены два JUnit на незарезервированное задание и повторное назначение после сохранения/загрузки. Статус нового полного Forge/Gradle прогона не подтверждён; ручная P5 остаётся открытой.

## P5 — сохранение заданий при выгрузке чанка (09.10.2026)

- Рабочий контроллер Citizen теперь **не проверяет мир и не удаляет опубликованные задания**, если цель находится в незагруженном чанке: такие задачи временно пропускаются при поиске, а активный исполнитель прерывает локальный маршрут и освобождает временную аренду, сохраняя запись в Job Board.
- `assign` для ручной работы также не проводит анализ блока незагруженной цели.
- `ProductionService.reconcile` больше не удаляет FARMING/CRAFTING, когда чанк не загружен, и не исследует незагруженную станцию при публикации нового задания.
- Добавлен GameTest `unloadedProductionJobsSurviveReconciliationWithoutForceLoading`: проверяет, что два дальних задания переживают сверку производства и несколько тиков NPC, не загружая удалённые чанки. Удаляет тестовые работы после проверки.
- **Статус:** исходники и GameTest добавлены; полный Java17 Gradle/Forge прогон пока не произведён. Прогон обязателен перед закрытием P5.
