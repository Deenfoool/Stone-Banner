# Stone & Banner — Настройки при создании мира

> **Предложение пользователя от 8 октября 2026:** добавить настройки Stone & Banner в стандартный экран создания мира Minecraft. **Статус: дизайн утверждён как направление, UI и серверные настройки ещё НЕ реализованы.**

## Основной UX

- В **ванильном** `CreateWorldScreen` появляется кнопка **«Настройки Stone & Banner»**, открывающая отдельный экран, затем возвращающая к исходному экрану создания мира без потери seed, режима игры, правил, имени и пакетов данных.
- Не подменять всю ванильную форму и не переопределять её `onCreate()`: такой путь вероятнее конфликтует с модами на создание мира, меняет слишком много и усложняет совместимость.
- Экран имеет три видимых раздела: **Государства**, **Политика и война**, **Кампания**. Подробный блок **«Производительность»** — раскрываемый, не перегружать первое знакомство.
- Вверху пресет: **Спокойный мир / Стандартная кампания / Эпоха войн / Свои настройки**. Редактирование поля переводит пресет в `CUSTOM`; сброс возвращает ровно значения выбранного пресета. Подсказка объясняет игровой эффект, не обещая прямого управления исходом.
- Все подписи локализованы как минимум ru_ru/en_us (расширить на de_de/zh_cn по существующему плану); клавиатура, Tab, Narrator, масштаб 2–4, 1280×720 и безопасный выход ESC/Back обязательны.
- Над кнопкой **«Создать мир»** в нашем экране только **«Применить и вернуться»**. Само создание выполняется оригинальной ванильной кнопкой **«Создать новый мир»**.

## Предлагаемая спецификация параметров

| ID / отображаемое имя | Тип / допустимые значения | По умолчанию | Игровая семантика |
| --- | --- | --- | --- |
| `factionCount` / ИИ-государства | целое 0–10 | **7** | Количество начальных политических слотов, без игрока; 0 = нет стартовых государств, 10 = максимум при старте; не гарантия готового физического города в каждом незагруженном регионе |
| `startBalance` / Силы держав | `HYBRID` на первом релизе | **HYBRID** | Разное начальное развитие: зрелые, молодые, зарождающиеся. Позже возможно расширение, но выбранный продуктовый старт — гибрид |
| `aggression` / Агрессивность | `LOW / NORMAL / HIGH` | **NORMAL** | Влияет на Utility AI для войны/налётов, но не задаёт сценарий гарантированной войны |
| `factionSpacing` / Расположение | `FAR / NORMAL / NEAR` | **NORMAL** | Плотность/дальность регионов государства, а не изменение ванильной генерации биомов или принудительная загрузка чанков |
| `allowNewStates` / Новые государства | bool | **true** | Возможность независимым общинам создать новые державы при игровых предпосылках; при ручном выборе factionCount=0 автоматически становится false (можно включить обратно); начальное количество не обязано оставаться постоянным |
| `diplomacyEnabled` / Дипломатия | bool | **true** | Соглашения, союзы и вассалитет доступны NPC и игроку при наличии реализации; при off нужны ясные нейтральные правила |
| `aiWarsEnabled` / Войны ИИ | bool | **true** | Разрешает ИИ инициировать войны друг с другом при достаточной причине; не отменяет защиту от мобов или последствия атак игрока |
| `newCampGraceDays` / Защита первого лагеря | 0 / 7 / 14 игровых дней | **7** | Временное ограничение **инициированных ИИ-государствами** агрессивных атак на первый лагерь игрока с момента его основания. **Не** бессмертие, не защита от обычных мобов; прямая агрессия игрока может отменить ограничение |
| `politicalFog` / Неизведанная политическая карта | bool | **true** | Политические границы/события раскрываются через разведку/контакт/слухи; не скрывает ванильный мир |
| `victoryMode` / Условие победы | `UNIFICATION / SANDBOX` | **UNIFICATION** | Объединение региона дипломатией и/или войной с финальным испытанием; sandbox — без экрана кампанийной победы, но с живым миром |
| `backgroundSimBudget` / Дальняя симуляция | `CONSERVATIVE / BALANCED` | **BALANCED** | Серверный бюджет для планирования вне области игрока; никогда не разрешает удалённо редактировать незагруженные блоки |

**Инварианты (не превращать в пользовательские читы):** NPC государства не получают бесконечные ресурсы/армии; мир остаётся физическим; ничто не строится из воздуха в незагруженных чанках; экономика и право владения проверяются сервером.

## Пресеты

| Параметр | Спокойный мир | Стандартная кампания | Эпоха войн |
| --- | --- | --- | --- |
| Государства | 5 | **7** | 9 |
| Агрессия | LOW | **NORMAL** | HIGH |
| Размещение | FAR | **NORMAL** | NEAR |
| Защита первого лагеря | 14 дней | **7 дней** | 0 дней |
| Возникновение новых держав | да | **да** | да |
| Дипломатия | да | **да** | да |
| Войны ИИ | да (редко, по причинам) | **да** | да (чаще, по причинам) |
| Политический туман | да | **да** | да |
| Победа | UNIFICATION | **UNIFICATION** | UNIFICATION |
| Дальняя симуляция | BALANCED | **BALANCED** | BALANCED |

**Поведение нуля:** установка `factionCount=0` на экране автоматически переводит `allowNewStates=false`. При желании игрок вправе после этого включить `allowNewStates=true`, получив мир без стартовых государств, но с их возможным естественным появлением. Это не отключает нейтральные ванильные деревни, мирных NPC и личное основание поселения. При N=1 межгосударственные войны на старте невозможны без второго государства. При N=10 действуют те же CPU-лимиты, что и при N=7.

Игра по умолчанию использует **Стандартную кампанию**, не `CUSTOM`. Количество политических слотов задаётся при создании мира; новые державы появляются/исчезают уже по обычным правилам.

## Техническое внедрение в Minecraft 1.20.1 / Forge 47.4.23

**Встраивание UI**

- Существующий `ClientScreenEvents` уже использует `ScreenEvent.Init.Post` + `event.addListener` для кнопок в `TitleScreen` и `PauseScreen`. Аналогично **только при** `event.getScreen() instanceof CreateWorldScreen` показывать кнопку настройки; не переписывать ванильный `CreateWorldScreen`.
- Изолированный `StoneBannerWorldCreationScreen` — экран-ребёнок с черновиком параметров, получающий ссылку на исходный `CreateWorldScreen`. ESC закрывает без применения; «Применить» сохраняет черновик для **данной конкретной сессии создания мира**, не в глобальном `ClientConfig`.
- Провести проверку раскладки ванильных кнопок, GUI Scale и сторонних модов на этот экран. Если кнопка перекрывает интерфейс, предпочесть адаптивное размещение/компактную ссылку; не удалять чужие виджеты.
- Не записывать gameplay параметры в `ClientConfig`: это настройки камеры/клавиш одного клиента, не авторитетная конфигурация server/world.

**Перенос настроек в мир**

- В новом мире сохранять версионированный серверный `WorldCampaignSettings` (`schemaVersion`, seed/ID мира, исходный preset, раскрытые поля и флаг `initialized`) через world-scoped `SavedData` / эквивалентное серверное хранилище.
- Самая ответственная часть — **переход от клиентского создания мира к стартующему интегрированному серверу**. Реализовать и протестировать одноразовый, привязанный к идентичности нового мира bootstrap. Нельзя просто читать «последний выбранный TOML» после загрузки: это загрязнит другие сохранения или dedicated server. Убрать временное состояние после успешной/отменённой генерации.
- Dedicated server получает стартовые настройки через отдельный **серверный bootstrap-конфиг** при создании нового мира, затем использует сохранённый мир. Протокол клиент↔сервер передаёт **серверный снимок для отображения**, а не предоставляет клиенту право менять генерацию.
- После первого запуска `factionCount/startBalance/factionSpacing` **неизменяемы**; действия, разрешённые в текущем мире (например, дипломатические правила) можно добавить позднее как отдельную административную настройку с правами и явно определённой семантикой.
- «Повторно создать мир» должен предложить скопировать настройки оригинала вместе с seed (без сущностей, построек и истории). Обычное открытие старого мира alpha.49 применяет безопасный документированный fallback, **не размещает новые державы поверх построек автоматически**.
- Сначала отдельные unit/codec тесты настроек, затем GameTests на lifecycle и ручной integrated-client + dedicated-server smoke-tests. **Никаких заявлений о работоспособности до фактической сборки Java 17.**

## Этапы работ

- [ ] **W0 — Домен конфигурации:** immutable + validated settings, пресеты, seed/версии, unit/codec tests.
- [ ] **W1 — Vanilla UI hook:** кнопка в CreateWorldScreen, дочерний экран, применение/отмена, GUI Scale, локали.
- [ ] **W2 — World bootstrap:** атомарный handoff в мир, SavedData, create/re-create, отсутствие утечек в другой мир, выделенный сервер.
- [ ] **W3 — Faction initialization:** связать параметры с F0/F1 без искусственного спавна и принудительной загрузки регионов.
- [ ] **W4 — Поведение правил:** aggression, войны, новые державы, туман, защита первого лагеря, условия победы и budget имеют **реальные** проверяемые последствия после внедрения соответствующих систем.

**Критерии приёмки:** параметры 0/1/5/7/9/10 сохраняются раздельно в разных мирах, ноль не создаёт стартовых ИИ-государств и не сбрасывает независимые деревни; ESC не применяет изменения; отмена создания не оставляет bootstrap; конфигурация мира восстанавливается после перезапуска; dedicated server не зависит от клиентского файла; `CreateWorldScreen` и ванильные seed/data packs/структуры/режимы игры работают без регрессий; значения соответствуют фактическому игровому эффекту.
