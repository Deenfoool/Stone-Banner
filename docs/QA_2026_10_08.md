# Проверка alpha.49 — 8 октября 2026

База: `main`, коммит `82a35d7`. Исправления остаются локальными; публикация не выполнялась.

## Найдено и исправлено

- Сборка Java 17: неверный пакет `ClipContext`, недопустимый `instanceof` для уже типизированного `BlockHitResult`, неоднозначный `BlockPos::getY` в компараторе разборки лесов.
- Смешанная очередь NPC: критические голод, усталость, опасность и травмы прекращают приказы; уже начатые системные маршруты к еде и сну не останавливаются очередью. Новые приказы в критическом состоянии отклоняются.
- Смешанная очередь NPC: права командира проверяются при добавлении и исполнении, после смены владельца старые приказы отменяются.
- Атака в очереди: исчезновение живой цели больше не считается победой. Следующий приказ допускается после подтверждённой смерти цели; исчезновение/выгрузка отменяет остаток очереди.
- JUnit-тест сетевой передачи чертежей: подготовлена таблица состояний блоков, которую в игре заполняет Forge. Проверки сетевых данных не ослаблены; причины неверного состояния и повторной ячейки теперь различимы.
- Строитель: устранён бесконечный повтор приказа в уже достигнутую клетку, когда фактический луч зрения перекрыт углом стены, а луч из идеального центра клетки проходит. Выбирается другая рабочая позиция; полный дом достраивается из физических материалов.
- Тест переселения: лагерь и путь ограничены загруженной изолированной площадкой, без пересечения соседних тестов и выгруженных чанков. Игровые ограничения навигации не ослаблены.
- Продолжение QA: обычные приказы местному помощнику учитывают его домашнюю территорию на всём A* маршруте, при подборе доступной точки возле цели и при перестроении. Смена домашней зоны отменяет запрещённый маршрут. Системные маршруты сохраняют предусмотренное исключение для возвращения домой/бегства; этот режим сбрасывается при остановке, завершении и ошибке движения.

## Пятый срез G7: запас MAINTAIN по общине

- `ProductionService.stock` определяет общину по владельцу заказа, а не по менеджеру контейнера или положению случайного NPC. В существующем радиусе 64 учитываются только загруженные склады её территории и рабочий груз её зарегистрированных жителей; личные предметы не учитываются.
- При смене членства груз пересчитывается по актуальной SavedData. Помеченные `SBProductionOwner` дропы должны совпадать с владельцем заказа и находиться внутри территории общины; чужие/непомеченные дропы не засчитываются. Происхождение предметов внутри сумки пока не моделируется.
- Производственные работы общины (фермерство/крафт) допускают её зарегистрированных жителей, сохраняя прежнюю проверку нанимателя. Это предотвращает выпуск неучитываемого груза сторонним работником. Для владельца без общины сохраняются прежняя общая сеть и правила допуска.
- Суммирование ведётся в `long` с ограничением результата `Integer.MAX_VALUE`; учёт не изымает предметы и не увеличивает `bill.made`. Возобновление после расхода использует существующую логику заказов.
- Добавлены шесть GameTest: свой запас/возобновление, чужой склад, груз и смена членства, дропы, допуск работника с сохранением ингредиентов, legacy-заказ. Изменения блоков ограничены тестовой площадкой; первоначальный прогон намеренно остановлен для пересборки уточнённого тестового источника, не считается результатом проверки.
- Первый завершённый прогон показал два несовпадения точного запаса в тестах своего склада/дропов: общинная территория включала зарегистрированные склады соседних тестовых арен. В новых эксклюзивных batch-сценариях отдельно сброшен только реестр складов GameTest-мира (не их блоки/предметы), добавлена проверка нулевого исходного запаса и точная диагностика.

## Шестой срез G7: права переносчика на подбор дропов

- Список предметов для выбора HAULING-задачи отфильтрован по работнику; перед реальным переносом каждого ItemEntity проверка повторяется. Смешанная кучка не даёт права на чужие предметы. Глобальная валидность задачи по-прежнему учитывает все дропы: отказ одному NPC не удаляет работу другого.
- Помеченный `SBProductionOwner` дроп владельца общины разрешён её зарегистрированному жителю, если найм не указывает другого работодателя. Без общины требуется совпадающий работодатель. Для обычных дропов у жителей действует территория лагеря; NPC без членства сохраняют legacy-подбор непомеченных предметов.
- Vanilla-получатель из NBT `Owner` проверяется отдельно от `Thrower`. В Minecraft 1.20.1 метод `getOwner()` возвращает сущность бросившего, а `setTarget(UUID)` задаёт получателя. Проверено по локальному классу Minecraft, без изменения сущности, reflection или access transformer.
- Добавлены семь серверных сценариев: смешанная кучка, потеря членства, отказ чужой задаче без её удаления, legacy-найм, vanilla-получатель/thrower, частичный подбор с сохранением остатка и территориальный доступ.
- Первый запуск остановился при компиляции теста из-за несуществующего `setOwner(UUID)`; исправлено на фактический `setTarget(UUID)`. Этот запуск не считается успешной проверкой.
- Это права на существующие физические дропы, не полная система происхождения вещей. Происхождение груза в NBT сумки, сохранение владельца при смерти/доставке и защита метаданных при vanilla-слиянии ItemEntity ещё открыты. Ручной подбор игроком не ограничен.
- Первый завершённый серверный прогон: все семь новых сценариев прошли, один старый legacy-тест запаса упал. Его абсолютное ожидание четырёх палок зависело от отсутствия рабочего груза соседних арен в общем радиусе 64. Тест теперь проверяет точный прирост `baseline + 4`, достижение этого целевого запаса и возврат к `baseline` после удаления собственного груза; чужие инвентари не очищаются. ## Седьмой срез G7: происхождение рабочего груза

- У рабочего слота появился необязательный `CargoOwner` UUID; он сохраняется в NBT инвентаря, а не ItemStack. Одинаковые предметы разных владельцев или legacy-груз без владельца не объединяются между собой. Частичная выгрузка сохраняет владельца, очистка слота удаляет его. Старые сохранения без UUID остаются совместимыми.
- Подбор сохраняет метку существующего дропа; для непомеченных предметов используется община/наниматель собирающего NPC. Собранная добыча работника получает его общину/нанимателя, урожай — владельца поля, результат крафта и остатки рецепта — владельца заказа.
- Поиск склада учитывает одновременно право доставки конкретного владельца и возможность принять его стек. Проверка повторяется в пути и перед вставкой каждого слота; чужой груз не выгружается вместе со своим. Без общины владельца сохраняется legacy-сеть с запретом при несовпадающем работодателе, включая незавербованных legacy-производственных работников. После успешной вставки предметы входят в территориальный запас склада: индивидуальная собственность внутри контейнера не введена.
- MAINTAIN для помеченного груза использует владельца слота, не текущее членство носителя. Для legacy-груза без владельца остаётся прежнее правило членства/общей сети. Учитываются только физически загруженные NPC в прежнем радиусе 64.

При возврате NPC в деревню личные вещи переносятся восстановленному жителю, рабочий груз выпадает с меткой и публикуется на переноску, а не превращается в личный запас деревни.
